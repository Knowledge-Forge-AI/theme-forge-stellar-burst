## Scope and method

The projection evaluates the complete tracked SVG blob set at the four
revisions recorded below. It is counterfactual architecture evidence, not an
implemented `tfsb analyze` result, a complete target-profile parser result, or
an import claim. All numeric classifications are provisional bounds.

The evaluator `tools/project-v0.3-compatibility.mjs` is a non-package profile
classifier. It reads isolated `git archive HEAD` exports, walks without
following symlinks, decodes UTF-8 fatally, invokes the compiled schema-1 parser
for the current baseline, inventories XML independently, and evaluates every
file against six cumulative stages. It accepts both SVG `version="1.0"` and
`version="1.1"` as explicit canonicalizations. Diagnostics and normalizations are counted
per file, so a file with several features contributes once to its exclusive
classification while remaining visible in every applicable diagnostic count.

The helper deliberately does not implement complete presentation numeric/enum
validation, transform argument/arity validation, path-data grammar, gradient
stop/value and local-paint type resolution, complete ID grammar, definition-
only reference authority/cycles, every XML placement/accessibility rule, or the
eight-level/1,024-modeled-element target-profile bounds. Implementing all of
those here would create a second analyzer before TFSB31. Consequently these
counts may over- or under-classify files and are not release acceptance gates.
The machine artifact records this limitation set explicitly.

Two independently written JSON results were byte-equal and had the digest
above. No source content, absolute input path, title/description, path data, or
attribute value is present in the machine result. Samples are limited to five
relative paths per diagnostic.

The four source worktrees were identified by `remote.origin.url`, were clean,
and were not fetched, built, installed, checked out, reset, or otherwise
mutated. Exports and measurement output lived outside every checkout.

## Classification semantics

- **Direct** means the source is accepted without operator normalization
  authority.
- **Normalize** means every relevant construct has a typed representation, but
  at least one named exact or intentional normalization needs authorization.
- **Unsupported** means the file is inert but contains an unmodeled construct,
  invalid typed value, or a feature introduced only at a later cumulative
  stage.
- **Unsafe** means active content, unsafe declaration/attribute, or external
  reference was found independently of parser failure order. Unsafe dominates
  unsupported and can never be normalized.

Every external file has zero Direct classification under this provisional
classifier because these revisions require accessibility authority, root
presentation promotion, or another explicit normalization. TFSB31 must confirm
the authoritative result. This is an authority projection, not an assertion
that all compatible mappings change visual semantics.

## Combined-feature effect

Files requiring two or more proposed profile features number 2,246 in Lucide,
0 in Simple Icons, 6,410 in Tabler, and 7,637 in theSVG. This is why element
prevalence alone would overcount compatibility.

The cumulative gains are interpretable:

- Simple Icons reaches 3,453 only when title-only source can become `labelled`
  with generated IDs and no fabricated description.
- Lucide remains at 0 after accessibility alone, rises to 1,230 after typed root
  presentation/currentColor and 2,145 after primitive preservation.
- Tabler's 6,184 individual outline/filled icons become eligible together at
  the presentation stage. The 225 active sprite files remain unsafe, and one
  additional file retains unsupported profile features.
- theSVG gains many per-file path icons, but the result is not a warehouse
  lifecycle target: 4,426 files remain unsupported/unsafe and identity
  collisions independently affect 12,444 files.

## TFSB31 discrepancy policy

The proposed v0.3 profile remains recommended for implementation, but no exact
row above is a release requirement. TFSB31 must:

1. produce authoritative two-profile counts over the same pinned tracked-blob
   exports with its complete inventory/classifier;
2. stop completion on any discrepancy and report the exact rule/files/count
   delta without changing implementation to make this artifact pass;
3. update the architecture and both projection artifacts through a reviewed
   commit before accepting corrected authoritative counts;
4. prove unsafe dominance and that matrix/skew, symbol sprites, CSS, clipping,
   masks, filters, external references, and active content remain outside the
   target profile;
5. keep complete-corpus analysis read-only while imports/lifecycle tests remain
   collision-free shards of at most 128 assets; and
6. infer no legal or redistribution conclusion from any count.

The high provisional per-file theSVG result is intentionally not a v0.3
acceptance target for import. theSVG remains combined unsupported/unsafe and
identity-rejection evidence, plus a backlog for future explicitly typed
decisions.
