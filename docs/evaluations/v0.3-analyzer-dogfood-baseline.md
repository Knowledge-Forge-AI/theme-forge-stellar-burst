## Authority

The corrected product analyzer output in this report is the current
authoritative v0.3 compatibility baseline for the pinned revisions. TFSB31R1
was correct for the analyzer then implemented. TFSB32 review subsequently
found that `commonV03` omitted accepted canonical local-gradient fallback
syntax. TFSB32R1 corrects that omission and supersedes the prior product
baseline for TFSB33 through TFSB35. The machine artifact retains the prior
phase, analyzer commit, and artifact digest as historical authority.

The earlier projection remains useful historical architecture evidence: it
records the intended staged profile, its deliberately omitted constraints, and
the numbers used before the complete product classifier existed. Its original
JSON bytes and provisional counts remain unchanged.

Compatibility is only one acceptance dimension. A normalizable file is not
thereby lifecycle-importable. Identity collisions, the 128-asset mutation
limit, explicit normalization authority, source-tree safety, and legal,
trademark, attribution, and redistribution review remain separate gates.

## Source safety is not profile measurement

The full tracked export asks whether the exported repository tree is a valid
analyzer directory source. The regular-SVG corpus asks how tracked regular SVG
blobs classify. A source-snapshot failure supplies no compatibility count.

| Corpus | Full-export result | Complete profile data | ZIP result |
| --- | --- | --- | --- |
| Lucide | accepted; `error` / exit 1 because the complete result contains unsafe SVGs | yes | complete regular inventory accepted; profile-equal |
| Simple Icons | rejected; `error` / exit 1; `ANALYZE_SNAPSHOT_FAILED` | no | not run; a complete faithful export contains a non-regular entry |
| Tabler Icons | accepted; `error` / exit 1 because the complete result contains unsafe SVGs | yes | complete regular inventory accepted; profile-equal |
| theSVG | accepted; `error` / exit 1 because the complete result contains unsafe SVGs | yes | complete regular inventory accepted; profile-equal |

For Lucide, Tabler Icons, and theSVG, directory, complete regular-inventory ZIP,
and regular-SVG corpus profile aggregates are equal. This grounds the
regular-SVG construction independently before using it for Simple Icons.

Simple Icons has one non-regular tracked entry: `.nvmrc`, Git mode `120000`,
blob `070266a2687d844408b8aa5f33b641c2de388dc9`. The product rejects the
traversed symlink with `ANALYZE_SNAPSHOT_FAILED` and the sanitized message
`The directory inventory contains a symbolic-link boundary.` It returns
`data: null`; no full-tree profile result is authoritative. The run did not
follow, remove, skip, or read through that link, and did not convert it into a
regular ZIP entry.

This is the v0.3 rule:

1. A full directory/export containing a traversed symlink fails closed.
2. Profile counts may use an evidence-only corpus of exact tracked regular SVG
   blobs. That corpus is a measurement projection, not proof that the original
   repository tree is directly accepted.
3. `tfsb analyze <repo>` gains no ignore-symlinks mode. A user may instead
   provide a safe directory or archive containing only intended regular SVG
   inputs. Collection filtering remains a v0.4 source-map/workspace problem.

## TFSB31R1-to-TFSB32R1 correction delta

ADR 0005 and both canonical SVG writers accept a typed local linear-gradient
paint with an optional six-digit fallback, serialized with one ASCII space as
`url(#paint-b) #123456`. The corrected analyzer recognizes that exact grammar
after XML attribute normalization and inventories `paint-b` as a local typed
paint reference. It does not broaden external or arbitrary `url(...)` syntax.

The correction changes no pinned dogfood classification. Two fresh corrected
runs reproduced every TFSB31R1 aggregate JSON and detail NDJSON digest exactly.
A tracked-blob scan found zero canonical local-gradient fallback occurrences in
all four regular-SVG corpora, so there is no bounded blob representative and no
count delta to attribute. Schema-1 counts are also byte-for-byte unchanged.

### theSVG reconciliation

The pinned projection was reproduced byte-for-byte from the regular-SVG
corpus before comparison, so these are classifier differences at one revision,
not changed-revision drift.

1. Two files move from Normalize to Direct under `commonV03`:
   `public/icons/devspace/default.svg` and
   `public/icons/ovhcloud/default.svg`. Both are exact
   `consumer_labelled` sources: root `role="img"`, no local title or
   description, and no conflicting accessibility attributes. ADR 0005 accepts
   that shape directly. The helper incorrectly required
   `accessibility_authority_required`; this is a projection-helper defect.
2. Three files move from Normalize to Unsupported under `commonV03` because
   the product enforces the complete ID grammar and reports
   `ANALYZE_INVALID_ID`:
   `public/icons/aws-res-amazon-api-gateway-endpoint/default.svg`,
   `public/icons/cody/default.svg`, and
   `public/icons/colgate/default.svg`. The projection explicitly omitted that
   complete grammar. This is an expected product-contract correction.
3. Four files move from Normalize to Unsupported under `commonV03` because
   they place `linearGradient` directly under the SVG root rather than in
   `defs`; product definition authority reports `ANALYZE_UNSUPPORTED_ELEMENT`
   and `ANALYZE_INVALID_REFERENCE`:
   `public/icons/matlab/default.svg`,
   `public/icons/mediawiki/wordmark-light.svg`,
   `public/icons/volcano/default.svg`, and
   `public/icons/zulip/wordmark.svg`. The projection omitted complete placement
   and reference authority. This is an expected product-contract correction.
4. Three files move from Unsafe to Unsupported in both profiles:
   `public/icons/azure-disk-encryption-sets/default.svg`,
   `public/icons/azure-maintenance-configuration/default.svg`, and
   `public/icons/azure-service-catalog-mad/default.svg`. Their paints are local
   `url(#...)` fragments containing digit-leading target IDs (such as
   `986fec79-...`) that violate the accepted ID grammar. The helper's narrower
   paint regex treated any unparsed `url(...)` as external. The product
   correctly reports `ANALYZE_INVALID_ID`, `ANALYZE_INVALID_REFERENCE`, and
   `ANALYZE_UNSUPPORTED_PAINT` instead of an unsafe external reference. This is
   a projection-helper defect.

Bounded representatives for every rule family were inspected directly from
Git blobs. No analyzer contract violation was found, so no TFSB31R2 product
correction is required.

## Acceptance disposition

TFSB33–TFSB35 use the corrected authoritative common-v0.3 table above, not the
provisional complete-profile rows or the superseded TFSB31R1 product phase.
The acceptance meaning remains bounded:

- TFSB33 owns explicit normalization and migration authority. A Normalize count
  predicts typed eligibility only; it grants no automatic transformation.
- TFSB34 may qualify only collision-free, legally reviewed, local-only shards
  of at most 128 assets. It does not raise limits or make theSVG a full-tree
  lifecycle target.
- TFSB35 consumes the same thresholds for release qualification after schema-2,
  normalization, migration, identity, legal, resource, and source-safety gates
  close independently.

The projection JSON remains immutable historical evidence. Its predeclared
`authority` block already names `tfsb-analyze-v1` as the authoritative producer
and marks its counts provisional; the projection report now links here. This
reviewed architecture/report/baseline update resolves the old instruction to
update both projection artifacts without falsifying or regenerating the
historical machine artifact.
